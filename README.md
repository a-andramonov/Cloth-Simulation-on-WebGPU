# Cloth Simulation — WebGPU + Position Based Dynamics

Простая модель симуляции ткани в браузере на чистом **WebGPU** (без Three.js, Babylon.js и других рендер-движков) — вся физика и отрисовка написаны с нуля на JavaScript + WGSL.

Тестовое задание на позицию в области 3D-графики. Квадрат ткани, подразбитый на треугольники, с закреплёнными углами и одной внутренней точкой, двигающейся по синусоиде — волны расходятся из центра.

## Возможности

- Интегрирование методом конечных разностей (явная схема **Verlet**) — гравитация и инерция без явного хранения скорости
- **Position Based Dynamics**: структурные связи между соседями + диагональные связи  против складывания сетки в ромб
- 4 закреплённых угла, 1 точка с управляемым колебанием (частота и амплитуда регулируются ползунками)
- Чекбокс включения/выключения гравитации
- Визуализация треугольной сетки прямо во фрагментном шейдере (без wireframe-режима — через `fract()` по мировым координатам)
- Вся физика считается на GPU через compute shaders; буфер частиц одновременно используется и как storage buffer (для физики), и как vertex buffer (для рендера) — без копирования данных между CPU и GPU каждый кадр

## Стек

- Чистый JavaScript (ES-модули), без сборщиков и зависимостей
- WebGPU API
- WGSL (WebGPU Shading Language)
- HTML/CSS для минимального UI

## Архитектура

Один общий `particleBuffer` (позиция + предыдущая позиция + тип точки на каждую вершину), который каждый кадр проходит через три стадии:

```
┌─────────────────────┐
│  Update params       │  время, флаг гравитации, частота/амплитуда волны
└──────────┬───────────┘
           ▼
┌─────────────────────┐
│  Integrate (compute)  │  Verlet: инерция + гравитация + волновая точка
└──────────┬───────────┘
           ▼
┌─────────────────────┐
│  Solve ×32 (compute)  │  PBD: стягивание соседей к целевому расстоянию
└──────────┬───────────┘
           ▼
┌─────────────────────┐
│  Render (draw)        │  тот же буфер читается как vertex buffer
└──────────┬───────────┘
           ▼
     requestAnimationFrame
```

`Integrate` и `Solve` — два независимых compute pipeline. Несмотря на идентичную структуру биндингов в WGSL, у каждого свой уникальный bind group layout (следствие `layout: 'auto'` — WebGPU не сравнивает layout по содержимому), поэтому под них заведены отдельные bind groups, даже когда оба ссылаются на одни и те же буферы.

## Как запустить

Нужен локальный HTTP-сервер — `file://` не сработает из-за ES-модулей (`<script type="module">`) и ограничений CORS на загрузку WGSL-шейдеров.

```bash
# любой вариант на выбор
npx serve .
# или
python3 -m http.server 8000
```

Открыть `http://localhost:PORT` в браузере с поддержкой WebGPU (актуальные версии Chrome/Edge; в Firefox и Safari поддержка пока ограничена или требует флагов).

## Известные ограничения и возможные улучшения

- **PBD вместо XPBD.** Текущая жёсткость связей зависит от числа итераций солвера и частоты кадров. 
- **Data race в solve-шейдере.** `solve_main` читает позиции соседей из того же буфера, в который одновременно пишет — несколько workgroup'ов GPU не гарантируют порядок видимости чужих записей внутри одного `dispatchWorkgroups`. 
- Нет ветра, взаимодействия мышью, разрыва ткани и самостолкновений — следующие кандидаты на доработку.
- Освещение отсутствует (плоская заливка по типу вершины) — можно добавить расчёт нормалей и простую Lambert-модель.
